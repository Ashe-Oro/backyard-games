# Build "Backyard Cornhole Wii 0.1.7", a Kinhank-ready release that retunes throw power by picker type, cleans up backswing/forward phase detection, and cancels a B release when there was no real forward swing, the way Wii Bowling does.

## Reference
- 0.1.6 on `main` at aa32726 (PR #66, tags `wii-v0.1.6` / `kinhank-v0.1.6`). Keep its controls: KOBE / NORMAL / SLIDER on the D-pad picker as the only height/arc control, swing speed = power, sideways swing = aim, no IR, no −/+ nudge. Keep the 0.1.6 phantom-throw fix (a held or unknown B at practice start does not grip until a fresh B-down in play) and the mid-match rule that a B already held during the bag flight or turn change can grip when the next turn opens.
- 0.1.6 mapping (same for every picker position): `power = clamp(0.55 * peak / full_speed, 0, 0.76)` with default `full_speed = swing_speed(1.9) = 3.344 m/s`. A clipped forward lobe still jumps to the 0.76 cap. Board deck from release: **7.7796–8.9795 m**. In 0.1.6 a calm centered NORMAL at the cap lands at 8.90 m; a capped SLIDER lands at 9.79 m (past the deck); a capped KOBE lands at 8.58 m. See `WII-0.1.6-LOG.md` and `wii/tests/game_test.c` `test_swing_to_landing`.
- Ashe, 1:03 PM ET Nov 22, 2026, after thinking aloud, final answer: "Require thirty percent more power for a slider. ... require twenty percent more power on normal and reduce ... by ten percent power on a Kobe." Context: a NORMAL is still too easy to send off the end of the board, and he needs to be able to swing harder on a Slider before it flies off the edge. Read it relative to 0.1.6 as:
  - SLIDER: a 30% harder swing is needed for the same power. Effective `full_speed` is ×1.30.
  - NORMAL: a 20% harder swing is needed. Effective `full_speed` is ×1.20.
  - KOBE: 10% less power for the same swing. Power is ×0.90, or equivalently effective `full_speed` is ×(1/0.9), whichever fits the code. Log which one you used.
- Ashe, 1:06 PM ET, after turning on the 1+2 debug overlay (last throw speed, peak, last power): the phase readout (READY → GRIP → BACKSWING → FORWARD SWING) is "not very accurate in the back and forward," so "take another look at how you're measuring the accelerometers and clean up your signal on backswing and forward swing."
- Ashe, 1:06 PM ET: "I should be able to press B to go into phase grip, but if there's no speed, then I let go of B, it should not throw the bag. Just like Wii bowling, it would just go back to phase ready." This overrides 0.1.3's "letting go of B always throws a weak lob." 0.1.2 already cancelled a stationary B tap; restore and extend that Wii Bowling cancel.
- Current detector (`swing_phase_name` in `wii/source/core/swing.c`): internal phases are only READY / GRIP / PENDING / SPENT; BACKSWING vs FORWARD is inferred from `lobes`, `back_apex`, `back_motion_ms`, `confirmed`, and a continuous-lobe dip/rise split (`SWING_DIP_RATIO` / `SWING_RISE_RATIO`). Peak speed can include motion that is not a classified forward stroke. Raw Wiimote accelerometer samples include gravity, pendulum-arc sign flips, and noise; a raw axis sign is not a reliable back/forward switch. Use real Wiimote reference (WiiBrew accelerometer docs, Wii Sports Bowling analyses, and the existing shoulder-pivot model in `wii/tests/bowling_trace.h`) when redesigning the signal path.
- Existing host tests that expect a B tap, a tiny motion, or a backswing-only release to emit a weak fallback throw must be rewritten for the new cancel. Do not leave those 0.1.3 assertions in place.

## Details
1. Per-type power, relative to the 0.1.6 default profile. Apply the scale across the whole linear range, including where the max-power cap is reached, so a swing that previously sat on the 0.76 cap is not still 0.76 unless the player actually swung the extra amount. Preferred shape: `power = clamp(0.55 * peak / (full_speed * type_scale), 0, 0.76)` with `type_scale` 1.30 / 1.20 / (1/0.9 or the power×0.90 equivalent). If you scale power and the cap directly instead, keep the cap in the same proportion (SLIDER 0.76/1.30, NORMAL 0.76/1.20, KOBE 0.76×0.90) and log that choice. Use the active D-pad picker (0 SLIDER / 1 NORMAL / 2 KOBE) at preview and at release. SET POWER may still retune the shared `full_speed` so an easy toss can reach the hole; the per-type scale stays on top of that profile. Weak-fallback power constants can remain in the headers if unused, but a cancelled release must not emit a throw. Leave aim, curl, the picker, no-IR, and no −/+ nudge alone.

2. Clean up backswing and forward-swing detection. Review the current phase detector against how a real Wiimote accelerometer behaves during a bowling-style swing (gravity in the sensor frame, pendulum arc, sign flips, noise, ~100 Hz 10-bit reports). Improve the signal so the overlay's BACKSWING and FORWARD labels track the true motion. Allowed tools: filtering or smoothing, gravity compensation from the steady-state / grip vector, hysteresis and minimum-duration thresholds, and detecting the backswing-to-forward transition at the reversal point rather than by raw sign. Measure peak speed only during the classified forward swing, so power numbers and the new per-type scaling stay consistent. Overlay names stay READY, GRIP, BACKSWING, FORWARD, RELEASE, SPENT. Do not reintroduce a stillness or settle-time gate on grip; B-down still grips immediately.

3. Wii Bowling cancel: B-down still enters GRIP immediately. If B is released during GRIP, or before a real forward swing is detected (above a minimum speed, or past the forward-swing threshold you choose and document), cancel: return to READY, do not throw, do not count a throw, `practice_throws` stays unchanged, no bag in flight. The same cancel applies if a backswing happened with no meaningful forward swing, and to a tiny wiggle that never crosses the forward threshold. A normal back-and-forward swing that crosses the threshold still throws on B-up during the forward swing, with power from the forward peak only. Auto-release / timeout without a real forward swing must also cancel, not weak-lob. Keep 0.1.6's phantom-throw protection and the mid-match held-B grip rule.

4. Version 0.1.7 on the STRAP ON! screen and the in-game HUD footer, matching `VERSION` in `wii/Makefile` and `kinhank/Makefile`, `BYC_VERSION`, `wii/hbc/apps/backyardcornhole/meta.xml`, install/README/BUILD docs that show the version, and new `## [0.1.7]` entries in `wii/CHANGELOG.md` and `kinhank/CHANGELOG.md`. Do not rewrite historical entries. Keep the KOBE / NORMAL / SLIDER labels. Update `wii/INPUT.md` for the per-type mapping, the cancel rule, and any detector change that players or tests rely on.

5. The arcade and web trees are untouched. Do not force-push, do not print or persist tokens, do not contact Retro, do not `git push`, do not open a PR, and do not install on the Kinhank. Do not run `make -C wii release`, `make -C kinhank`, or the Dolphin e2e; the reviewer will run those after your host tests are green.
