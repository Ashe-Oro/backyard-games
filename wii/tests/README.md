Host input tests: `make -C wii host-test` or `sh wii/tests/run-input-tests.sh` from the repo root. The shell runner also works from another directory and deletes its temporary executables.

`input_test.c` exercises deterministic synthetic accelerometer samples, the exact time-weighted speed window, retained forward peaks, B-release latency, back-apex rejection, arming, clipping, aim/curl locks, menu/play buttons, two remotes, pass-and-play, disconnect/reassignment and comfortable-toss calibration. `wpad_test.c` links the actual adapter against a test-owned API double in `fake/`, covering queue draining, registration errors, reconnect, error/data flags, dropped counts and estimated timestamp gaps. The fake header never belongs in a Wii build's include path.

Use a C11 host compiler with libm; neither devkitPPC nor a renderer is needed. Assertions must remain enabled. The fake-WPAD tests verify our adapter contract, not the Bluetooth stack or a real libogc link. Recorded real-remote traces, independent video speed labels and the blocking P1 hardware gates remain required. Physics golden-vector tests are Track C work.
